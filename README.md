# Разработка MCP-серверов в 1С

Инструмент для создания MCP (Model Context Protocol) серверов на платформе 1С:Предприятие. Позволяет разрабатывать расширения 1С, которые предоставляют данные и функциональность базы для AI-ассистентов (чаты с языковыми моделями, Claude Desktop, Cursor и других AI-клиентов).

Подробное видео о проекте и его возможностях:  
[VK Видео](https://vkvideo.ru/video-219359576_456239024) | [Youtube](https://youtu.be/ZEla85JsfCo) | [Rutube](https://rutube.ru/video/ba1c64432d1a5b6cfd2335b83bf47071/)

Проект содержит готовое расширение для 1С, которое берет на себя всю техническую рутину протокола MCP. Вам остается только реализовать бизнес-логику ваших инструментов. Инструменты для работы с метаданными конфигурации 1С и запросами доступны "из коробки".

## Как это работает: Концепция MCP

Качество ответа языковой модели (LLM) напрямую зависит от качества предоставленного ей контекста. Подготовка такого контекста вручную может быть трудоемкой.

**Model Context Protocol (MCP)** — это открытый стандарт, который позволяет модели самой запрашивать необходимые данные через специальные "инструменты" (tools), предоставляемые вашим сервером. Таким образом, контекст для решения задачи собирается автоматически.

## Компоненты проекта

- **`src/edt/`** — расширение MCP-сервера в формате проекта 1C:EDT.

## Встроенные инструменты

### Метаданные конфигурации

- `list_metadata_objects` — поиск объектов метаданных по типу и имени
- `get_metadata_structure` — структура объекта (реквизиты, ТЧ, перечисления и др.)

### Работа с запросами

Позволяет AI-модели автономно исследовать данные в базе 1С:

- `execute_query` — выполнение произвольных запросов с параметрами и пагинацией
- `validate_query` — проверка синтаксиса без выполнения
- `parse_nav_link` / `get_nav_link` — конвертация навигационных ссылок

Примеры запросов к ассистенту:

```
Найди все непроведённые документы за последнюю неделю
```
```
Покажи задолженность и последние 5 операций по контрагенту:
e1cib/data/Справочник.Контрагенты?ref=...
```

> [!CAUTION]
> **Безопасность данных:** При использовании AI-моделей для запросов к базе данные передаются на внешние серверы. Убедитесь, что:
> - Не запрашиваете персональные данные (ФИО, паспорта, адреса, телефоны)
> - Используете локальные LLM для работы с конфиденциальными данными
> - Ограничили права пользователя, от имени которого выполняются запросы

## Быстрый старт

### Шаг 1: Установка расширения 1С

Подключите готовое, собранное расширение из каталога `build/MCP_Сервер.cfe` в вашу конфигурацию.

### Шаг 2: Публикация HTTP-сервиса

Опубликуйте на веб-сервере HTTP-сервис `mcp_APIBackend`, который находится в расширении.

> **Важно:** Регистр имени базы в URL должен точно совпадать с именем публикации (например, `base`, а не `Base`). Несовпадение регистра приводит к редиректам, которые превращают POST-запросы в GET.

### Шаг 3: Подключение AI-клиента

Подключите MCP-клиент (например, Cursor) напрямую к опубликованному HTTP-сервису:

```text
https://host/имя_публикации/hs/mcp/
```

Аутентификация выполняется через **базовую аутентификацию HTTP** — заголовок `Authorization: Basic …`. Логин и пароль пользователя 1С кодируются в Base64 и передаются в каждом запросе клиента к сервису.

Примеры настроек для разных клиентов — в папке [`mcp_client_settings/`](./mcp_client_settings/).

## Подключение с базовой аутентификацией

Схема: `AI-клиент ←→ HTTP-сервис 1С`.

Клиент должен уметь remote MCP (Streamable HTTP) и передавать произвольные HTTP-заголовки.

### Получение значения для заголовка

В 1С строку для Basic Auth можно получить так:

```bsl
Base64Строка = ПолучитьBase64СтрокуИзДвоичныхДанных(
	ПолучитьДвоичныеДанныеИзСтроки("" + Пользователь + ":" + Пароль));
```

В заголовок подставляется значение вида `Basic <Base64Строка>`.

### Пример для Cursor (`mcp.json`)

```json
{
  "mcpServers": {
    "1c-server": {
      "url": "https://host/имя_публикации/hs/mcp/",
      "headers": {
        "Authorization": "Basic <Base64Строка>"
      }
    }
  }
}
```

Глобальный файл настроек Cursor: `%USERPROFILE%\.cursor\mcp.json` (Windows) или `~/.cursor/mcp.json`.  
Проектный: `.cursor/mcp.json` в корне репозитория.

Вместо литерала можно использовать переменную окружения, если клиент это поддерживает:

```json
"Authorization": "Basic ${env:MCP_1C_BASIC}"
```

где `MCP_1C_BASIC` — уже готовая Base64-строка `пользователь:пароль` (без префикса `Basic`).

## Разработка собственных инструментов

Функциональность расширяется добавлением собственных инструментов для взаимодействия с данными 1С.

### Вариант 1. Разработка внутри движка

- **Шаг 1:** В расширении создайте новую обработку и включите ее в подсистему `mcp_КонтейнерыИнструментов`.

- **Шаг 2:** В модуле менеджера этой обработки реализуйте два экспортных метода:

```bsl
// Метод для описания инструментов и их параметров
Процедура ДобавитьИнструменты(Инструменты) Экспорт
	// ... здесь вы описываете, какие инструменты предоставляет ваша обработка
КонецПроцедуры

// Метод для выполнения логики инструмента
Функция ВыполнитьИнструмент(ИмяИнструмента, Аргументы) Экспорт
	// ... здесь вы реализуете логику, которая будет вызвана AI-моделью
КонецФункции
```

### Вариант 2. Разработка в своем расширении

Подход такой же, но можно создать отдельное расширение для своих инструментов. В это отдельное расширение необходимо скопировать подсистему mcp_MCPСервер и добавить к ней префикс своего расширения (Например, МОЙ_mcp_MCPСервер). Движок находит подсистемы, которые в названии содержат mcp_MCPСервер и подключает их идентично своим.

Подробное руководство по разработке находится в файле [`src/edt/agents.md`](./src/edt/agents.md).

## Другие примитивы MCP

Помимо **Инструментов (Tools)**, проект также поддерживает **Ресурсы (Resources)** для предоставления статического контекста (например, файлов) и **Промпты (Prompts)** для заготовленных шаблонов сообщений.
