# Протокол клиентского агента MCP

Версия протокола: **1**.

Расширение MCP работает в HTTP-сеансе и не может ни показать пользователю окно, ни выполнить код на клиенте. Для этого служит **клиентский агент** - расширение, которое установлено в ту же базу и запущено в клиенте 1С под тем же пользователем, под которым подключён MCP. Эталонный агент - расширение Ei (EnterpriseIntegrator).

Через агента `execute_code` умеет:

- отдать человеку серверный код с опасными конструкциями в рабочей базе: человек выполняет его сам или отказывается;
- выполнить код на клиенте (`execution_context=client`): безопасный - сразу, с опасными конструкциями - тоже руками человека.

Опасный код агент выполняет сам, в том месте, которое просила модель: клиентский - в клиенте, серверный - серверным вызовом в сеансе пользователя. MCP получает результат, а не разрешение.

Расширения не ссылаются друг на друга в коде. Их связывает только этот протокол: ключи уведомлений, ключи хранилища и формат данных.

## Признак установленного агента

MCP считает агента установленным, если в метаданных сеанса есть общий модуль `ЗапросыMCPВызовСервера_Ei` и платформа 8.3.27.1606 или новее (в ней появились уведомления клиента). MCP обращается к `УведомленияКлиента` через `Вычислить("УведомленияКлиента")`, как БСП: режим совместимости MCP ниже 8.3.27. Ei обращается напрямую. Без агента:

- опасный серверный код в рабочей базе отклоняется, как раньше;
- `execution_context=client` отклоняется.

## Транспорт

| Направление | Механизм |
|---|---|
| MCP -> клиент | Уведомление клиента платформы: `УведомленияКлиента.ОтправитьУведомление(Ключ, Данные, НомераСеансов)` |
| Клиент -> MCP | Серверный вызов агента пишет ответ в хранилище общих настроек пользователя, MCP ждёт его, опрашивая хранилище |

Ответ нельзя вернуть уведомлением: HTTP-сеанс не подписывается на уведомления, `ПодключитьОбработчик` есть только в клиенте. Хранилище общих настроек - таблица платформы, новых объектов метаданных протокол не требует. Пользователю MCP нужно право «Сохранение данных пользователя».

Номера сеансов MCP и агент получают через `ПолучитьСеансыИнформационнойБазы()` в привилегированном режиме: оба расширения ставятся без безопасного режима.

## Уведомление «запрос»

- **Ключ:** `mcp_ЗапросВыполненияКода`
- **Адресаты:** номера клиентских сеансов пользователя MCP (тонкий, толстый, веб-клиент). Для `client` - один выбранный сеанс.
- **Данные** - `Структура`:

| Поле | Тип | Описание |
|---|---|---|
| `ВерсияПротокола` | Число | `1` |
| `Идентификатор` | Строка | UUID запроса |
| `Пользователь` | Строка | Имя пользователя ИБ, для которого запрос. Агент игнорирует чужие запросы |
| `Контекст` | Строка | `server` или `client` |
| `Код` | Строка | Код без изменений, как его прислала модель |
| `Хеш` | Строка | SHA-256 кода (UTF-8), hex |
| `ОпасныеКонструкции` | Массив из Строка | Найденные конструкции, для подсветки |
| `ТребуетсяПодтверждение` | Булево | `Ложь` только для `client` без опасных конструкций |
| `Создан` | Дата | Универсальное время создания |
| `СрокДействия` | Дата | Универсальное время, после которого ответ не принимается |

## Уведомление «запрос закрыт»

- **Ключ:** `mcp_ЗапросВыполненияКодаЗакрыт`
- **Данные:** `Структура` с полями `Идентификатор` (Строка) и `Причина` (Строка).
- Отправляют обе стороны: агент - после записи ответа, MCP - после того как забрал ответ или срок истёк. Агент отвязывает строку запроса с этим идентификатором: дальше это обычный вариант набора.

## Запрос у MCP

Между вызовами `execute_code` MCP хранит запрос в `ХранилищеОбщихНастроек`: ключ объекта `mcp_ЗапросыВыполненияКода`, ключ настроек - `Идентификатор`. Значение - поля уведомления «запрос» без `Код` плюс `НомераСеансов` (Массив из Число), куда ушло уведомление. Агент эти записи не читает. Срок действия запроса - 600 с; просроченные запросы и ответы на них MCP удаляет при создании нового запроса.

## Ответ

`ХранилищеОбщихНастроек`, ключ объекта `mcp_ОтветыНаЗапросыКода`, ключ настроек - `Идентификатор`, пользователь - текущий. Значение - `Структура`:

| Поле | Тип | Описание |
|---|---|---|
| `ВерсияПротокола` | Число | `1` |
| `Идентификатор` | Строка | Из запроса |
| `Хеш` | Строка | Из запроса |
| `Создан` | Дата | Из запроса |
| `Контекст` | Строка | Из запроса |
| `Решение` | Строка | `Выполнено` или `Отклонено`. `Разрешено` - ответ прежних версий агента для `server`, после него код выполняет MCP |
| `НомерСеанса` | Число | `НомерСеансаИнформационнойБазы()` сеанса, который ответил. Заполняется на сервере в серверном вызове агента |
| `Ответил` | Дата | Универсальное время ответа |
| `Комментарий` | Строка | Причина отказа или пояснение пользователя для модели, может быть пустым. MCP отдаёт его в `user_comment` |

Только для `Решение = "Выполнено"`:

| Поле | Тип | Описание |
|---|---|---|
| `Успех` | Булево | Код выполнился без исключения |
| `Результат` | Произвольный | Значение переменной `Результат`. Если оно не сохраняется в хранилище настроек - его строковое представление. MCP сериализует его, как `data` обычного выполнения (таблицы, деревья, ссылки) |
| `ТипРезультата` | Строка | `Строка(ТипЗнч(Результат))` |
| `Ошибка` | Строка | Подробное представление ошибки, если `Успех = Ложь` |
| `Код` | Строка | Фактически выполненный код |
| `КодИзменен` | Булево | Пользователь изменил код перед выполнением |

Прежние версии агента вместо `Результат` писали `РезультатJSON` (Строка, JSON); MCP принимает любое из двух полей.

## Проверки MCP перед тем, как принять ответ

1. `Хеш` ответа совпадает с хешем кода в вызове `execute_code`.
2. Срок действия запроса не истёк.
3. Сеанс `НомерСеанса` существует, принадлежит тому же пользователю и является интерактивным клиентом (`1CV8C`, `1CV8`, `WebClient`). Ответ, записанный из HTTP-сеанса или фонового задания, отклоняется.
4. `Решение` допустимо для контекста, для `Выполнено` заполнены все поля результата.
5. Ответ одноразовый: MCP удаляет его из хранилища сразу после чтения. Ответ, не прошедший проверку, закрывает запрос.

В рабочей базе код `execute_code` не может обращаться к `ХранилищеОбщихНастроек`, `ХранилищеСистемныхНастроек`, `УведомленияКлиента`, `mcp_КлиентскийАгент` и модулям агента (`ЗапросыMCPВызовСервера_Ei`, `ЗапросыMCPКлиент_Ei`, `ЗапросыMCPКлиентПовтИсп_Ei`) даже с подтверждением, чтобы модель не подделала ответ или запрос.

## Что делает агент

- При запуске клиента подписывается на оба ключа.
- Для `client` сам проверяет код на опасные конструкции и не доверяет полю `ТребуетсяПодтверждение`: уведомление в копии базы может отправить любой код. Список берёт у MCP: `Обработки.mcp_ИнструментВыполнениеКода.НайтиОпасныеКонструкции(Код, "client")`. Если MCP в базе нет, считает код опасным.
- Клиентский код без опасных конструкций выполняет сразу, без участия человека, пишет замер в журнал выполнения Ei с идентификатором запроса и отправляет результат.
- Остальное добавляет в открытую форму Ei несохранённой строкой набора `MCP_<контекст>_<время создания>`: код - в варианте «Алгоритм», описание запроса - в варианте «Комментарий»; строка становится текущей. Если форма Ei закрыта, запрос ждёт в очереди сеанса, а пользователь видит оповещение со ссылкой на Ei.
- Согласие - штатная кнопка «Выполнить». Код можно изменить перед выполнением или выполнить только выделенный фрагмент. Код выполняется один раз и только там, где просил запрос (`ВыполнитьКлиентСервер_Ei.ВыражениеВМесте`): в клиенте или серверным вызовом Ei, без пробного `Вычислить` и без перехода с клиента на сервер. Запуск попадает в историю варианта и журнал выполнения Ei с идентификатором, равным идентификатору запроса. Результат уходит в ответ `Выполнено`, ошибка - тоже `Выполнено` с `Успех = Ложь`.
- Отказ - удаление строки. Текст, дописанный пользователем в «Комментарий» после описания запроса, уходит в поле `Комментарий`.
- После ответа или уведомления «запрос закрыт» строка отвязывается от запроса и остаётся обычным вариантом: её можно сохранить в набор или выполнить ещё раз, MCP об этом уже не узнает.
- В коде доступна переменная `Результат` и фиксированные функции Ei (`Параметры()`, `Клиент()`, `Пауза()`). Поддерживается только синхронный код.
- Перед записью ответа серверный вызов агента проверяет: запрос адресован текущему пользователю, сеанс - интерактивный клиент, решение допустимо для контекста, срок не истёк, ответа ещё нет. После записи отправляет «запрос закрыт» в клиентские сеансы пользователя.
- Каждое решение пишет в журнал регистрации, событие `Ei.ЗапросыMCP`, вместе с кодом.

## Реализация

| Сторона | Объекты |
|---|---|
| MCP | `mcp_КлиентскийАгент` - запрос, ожидание, проверки ответа; `mcp_ИнструментВыполнениеКода` - `execute_code`, списки конструкций, `НайтиОпасныеКонструкции` |
| Ei | `ЗапросыMCPВызовСервера_Ei` - проверка кода, запись ответа с результатом запуска; `ЗапросыMCPКлиент_Ei` - подписка при начале работы, строки `MCP_`, выполнение и отказ; `ЗапросыMCPКлиентПовтИсп_Ei` - связь строк с запросами и очередь на время сеанса; `ВыполнитьКлиентСервер_Ei.ВыражениеВМесте` - выполнение в заданном месте; точки вызова в `ВариантыКлиент_Ei.ВыполнитьВарианты` и `НаборВариантовКлиент_Ei.УдалитьСтрокуИПодстроки` |

## Последовательность

```
Модель -> execute_code (MCP, HTTP-сеанс)
  MCP: опасные конструкции / client -> запрос -> уведомление в клиентские сеансы пользователя
  MCP: ждёт ответ в хранилище до 40 с, проверяя раз в секунду в фоновом задании mcp_КлиентскийАгент.ОжидатьОтветВФоне (пауза - ожидание завершения самого задания)
Агент (клиент): безопасный client-код выполняет сразу; остальное - строка MCP_ в Ei
  Человек: «Выполнить» (код можно изменить) или удаление строки
  Агент: серверный вызов -> ответ Выполнено с результатом или Отклонено с комментарием -> «запрос закрыт»
  MCP: проверки -> берёт результат -> удаляет ответ -> «запрос закрыт»
Модель <- результат
  ...или, если ответа нет 40 с: status=pending_approval, request_id. Повторный вызов с тем же кодом и request_id ждёт ответ снова.
```
